## Product goal

Create a professional local web dashboard where users can discover, install, configure, run, monitor, update, and remove MCP servers without manually visiting GitHub, cloning repositories, or editing configuration files.

The system must support both technical and nontechnical users.

## Local application behavior

Create a local control-plane service with these startup rules:

1. Default to `127.0.0.1:3000`.

2. Check whether port `3000` is available before starting.

3. Never kill another process automatically.

4. If port `3000` is occupied, show the process information when permitted and provide:

   * a clear error;
   * a `--port` option;
   * an option to reuse the existing Global MCP instance if it is healthy.

5. Bind to `127.0.0.1`, never `0.0.0.0` by default.

6. Open the dashboard in the default browser only after the health endpoint reports ready.

7. Use a single-instance lock to prevent duplicate daemons.

8. Provide clean shutdown and process recovery.

Required commands:

```bash
global-mcp start
global-mcp stop
global-mcp restart
global-mcp status
global-mcp dashboard
global-mcp search <query>
global-mcp install <server-id>
global-mcp uninstall <server-id>
global-mcp update [server-id]
global-mcp list
global-mcp doctor
global-mcp clients
global-mcp configure <client>
global-mcp logs [server-id]
global-mcp registry sync
```

Every dashboard operation must have an equivalent CLI command and structured JSON output mode.

## Installation engine

Users must not need to run `git clone`.

Support verified installation strategies such as:

* npm packages;
* Python packages through isolated environments;
* downloadable signed releases;
* container images;
* GitHub source archives pinned to immutable commits;
* approved local binaries.

Never execute installation instructions copied directly from a README.

Before installation:

1. Resolve the exact version.
2. Pin an immutable revision.
3. verify the license;
4. calculate or verify checksums;
5. inspect install hooks;
6. display required permissions;
7. display filesystem, network, credential, and execution scope;
8. require explicit confirmation.

Install each MCP server into an isolated managed directory. Maintain a lockfile containing exact versions, hashes, sources, configuration, and ownership.

Provide:

* transactional installation;
* rollback;
* uninstall cleanup;
* dependency isolation;

* process supervision;
* stdout/stderr capture;
* timeout and restart policies;
* health checks;
* update detection;
* version comparison.

Never run arbitrary shell command strings. Use validated executable and argument arrays.
