# Commit and Release Policy

For the **Global MCP Control Plane** project, we strictly use `release-please` for automated changelog generation and release note posting.

To ensure this automation works flawlessly, you MUST ALWAYS follow these rules:

1. **Conventional Commits**: Every commit message must follow the Conventional Commits specification.
   - `feat: <description>` for new features (Triggers a MINOR release).
   - `fix: <description>` for bug fixes (Triggers a PATCH release).
   - `chore:`, `docs:`, `style:`, `refactor:`, `perf:`, `test:` for other changes (Does not trigger a release).
   - Append `!` (e.g., `feat!: <description>`) for breaking changes (Triggers a MAJOR release).

2. **Automated Changelogs**: NEVER manually edit `CHANGELOG.md` or create GitHub releases manually. The `release-please` GitHub Action handles this.

3. **Release Execution**: To publish a release and post the release notes, simply merge the automated "Release PR" generated by the bot in GitHub. Once merged, the bot will tag the repository and publish the release notes automatically.
